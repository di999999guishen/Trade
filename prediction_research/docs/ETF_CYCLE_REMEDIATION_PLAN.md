# ETF cycle 六项修订实施方案

创建：2026-09-06。基线提交：`0a14f9e`。授权顺序：先提交已有整合→持久化本方案→实施、验证并更新状态。本轮不接入 A 股个股、不恢复大模型调用、不自动下单。

## 交付目标与执行顺序

让每一份 ETF 预测能回答：使用了哪个资金流截面、何时可得、是否参与概率、结果何时冻结、从哪个开盘开始结算、缺了哪些数据。顺序为 R1→R2→R3→R5→R4→R6，依赖满足后自动继续，不按阶段请求确认。

| 阶段 | 对应问题 | 工程状态 | 真实数据状态 |
|---|---|---|---|
| R1 | 时间和可得性统一 | 已实现，时间边界及真实缓存验证通过 | 行情日、抓取日和实际决策时间分别展示 |
| R2 | 冻结结果和本轮报告一致 | 已实现，不可变返回及跨运行报告隔离测试通过 | 新 v2 记录与旧 v1 并存，旧记录不回填 |
| R3 | 资金流完整展示 | 已实现，实际报告已展示金额/排行/时间/窗口/概率口径 | 1 个资金流观察日，5/20 窗口如实显示不足 |
| R5 | 退出候选池后仍可结算 | 已实现，退出候选后更新集合及结算测试通过 | 真实缓存中部分历史粗筛标的缺行情，已列出 |
| R4 | 历史资金流筛选与策略检验 | 重建、成对 cohort、成本和筛选后样本外预测代码已验收 | 仅 1 日、全量合格池尚缺 1101 个行情序列，真实增益等待 |
| R6 | 失败、等待与数据新鲜度 | 已实现，失败矩阵及真实缓存闭环通过 | 状态为 complete_with_data_waits；本轮未执行真实联网刷新 |

## R1：时间统一

1. 引入显式 `decision_at_utc`（本轮决策时刻），与 `feature_date`（行情日期）、资金流 `observed_at_utc`、`available_at_utc`、冻结时间分开记录。
2. 独立历史预测默认用特征日配置的截止时间；cycle 明确记录本轮行情/新闻获取后的决策时刻。所有资金流附件和标准证据使用同一决策时刻筛选。
3. 资金流快照晚于决策时刻时，不得进入当时预测依据；保留不可用原因。报告可以显示观察数据，但必须标记决策时不可用。
4. 限制旧行情/旧资金流的复用，缺失或过期不冒充新数据；缓存模式明确是缓存验收。
5. 新格式预测结算从实际决策时刻之后的第一根交易日开盘开始，不从已经过去的开盘入场；旧记录保留旧标签规则。

验收：截止时刻前后 1 秒；周末发布；观察日/抓取日不同；未来截面拒绝；标签入场严格晚于决策时刻。

## R2：不可变预测与本轮绑定

1. 使用附属表保存完整冻结 payload，兼容已有 predictions 表，避免破坏旧记录和结果。
2. 幂等命中时，从数据库返回原冻结概率、证据、时间和 ID。新运行上下文与旧冻结结果分开标注，不给旧 ID 拼接新内容。
3. cycle 固定本轮筛选报告、候选、预测 ID、回测路径、整合路径。报告只消费这份上下文，不混用目录最新文件和数据库全局最近 6 条。
4. 旧记录没有完整 payload 时，只补充可从旧表确认的字段并标记 legacy；不以当前配置伪造历史资产信息。
5. 同日粗筛重复运行不覆盖原冻结选择；新的重放报告独立保存，不修改已经冻结/结算的历史。
6. 发布门同时检查样本量和 Brier 条件；本轮模型未通过即如实标记。

验收：同一身份输入新概率/新证据仍返回旧值；两轮不同候选的报告互不串用；大于 3 个候选不截断成 6 条；旧行兼容。

## R3：资金流展示

1. 主报告每只预测 ETF 展示：净流入金额、占比、观察时刻、首次可得时刻、决策时是否可用、资金流粗筛贡献、资金与价格方向是否一致，以及“参与粗筛、未参与概率”的明确说明。
2. 展示本轮来源截面的净流入与净流出金额榜，区分全源排行和通过筛选的候选，不将粗筛榜冒充金额榜。
3. 增加 5/20 个实际观察日累计净流入、覆盖日数、最近值；观察日不足或缺值显示 null/数据不足，不补零，不声称这些日期一定连续交易日。
4. 空值、非法数值不参与金额排行，不格式化为虚假零；缺失资金流不作为中性资金流给候选加分。
5. 报告引用冻结结果内的资金流，当前观察快照另列。保持成交单大小估计口径，不推断账户身份。

验收：正、负、零、缺失；同日多个快照只计一次；不足 5/20 日；金额榜与粗筛榜不同；预测附带字段与 Markdown 一致。

## R5：持续结算

1. 维护待更新集合：本轮候选 ∪ 未结算预测 ∪ 未结算粗筛选择 ∪ 待结算成功 ETF Agent。
2. 正常 cycle 更新上述集合的行情；缓存模式仍逐项报告缺行情或未到期。
3. 结算不依赖标的仍在当前 universes 中；明确列出 settled、waiting_for_bars、waiting_for_horizon。
4. 使用交易日行情行而非自然日计数；新预测使用 R1 的实际决策时刻，旧预测使用已有标签定义。

验收：候选轮换后旧标的仍更新/结算；缺行情原因可查；多次结算幂等；不因当前候选缺失而停止历史结算。

## R4：历史筛选与研究检验

1. 把现有筛选逻辑抽成纯函数供实时和历史共用，固定规则哈希。保存每次实时规则首次登记时间及完整规则。
2. 从数据库全市场截面重建每个历史观察日候选；已有真实冻结批次时使用其实际决策时间及原截面，否则使用当日配置截止时间。只接受相应决策时刻前已收到的截面，迟到数据不回填过去。当前规则用于登记前日期时只能标记为事后研究，不声称前瞻可得。
3. 对历史候选逐项连接随后行情标签；缺行情、未到期、迟到截面分别计数。覆盖不足时仍产出可审阅计划/报告，但不发布策略结果。
4. 同日期比较资金流候选、符合相同流动性条件的等权基线和动量候选；周期收益采用等权独立 cohort，明确重叠，不伪造连续组合净值或年化 Sharpe。
5. 报告扣除配置的往返成本后的 cohort 收益；不宣称成本包含真实滑点、市场冲击或涨跌停可成交性。不得对缺行情候选静默删样本后继续声称完整策略。
6. 原证据增益实验同时覆盖商品池与本轮候选池；仍保留对价格 v2/历史概率/动量的比较。真实观察日不足时等待，但历史重建与对照代码需完成并由合成时序测试验收。
7. 历史价格齐全且观察日达标后，再以每个历史截面当时已知的 ETF 池做量价滚动样本外预测，抽取资金流候选的概率并与历史概率基线比较；不使用未来候选池训练。决策延迟导致标签周期不一致时退出成对比较并记录原因。

验收：改变未来截面不改变过去选择；迟到截面拒绝；同日去重；筛选规则相同；缺历史不产收益结论；成本正确；成对 cohort 缺数据整组不纳入比较。

## R6：编排与状态

1. 分开记录 execution、data readiness、validation，外层传递 `complete_with_data_waits`，不把等待阶段当作全部能力完成。
2. 抓取/筛选失败时，阻断本轮新候选回测与预测，不读取旧最新筛选冒充本轮；历史结算、故障报告等独立步骤继续。
3. 每一步保存输入引用、状态、输出路径；即使部分失败也保存 cycle 和 Markdown。CLI 对 partial_failure 返回非零。
4. 数据新鲜度包含行情时刻、抓取时刻、缓存模式；本轮候选历史不足阻断预测，不影响待结算集合处理。
5. 不创建未要求的系统定时任务；每次 cycle 自动按依赖推进与重查就绪条件。

验收：抓取失败、筛选失败、候选为空、历史不足、证据等待、报告失败；无旧结果兜底；失败运行落盘；status/CLI/报告状态一致。

## 验证、交付与恢复

- 修改前的已提交基线为 `0a14f9e`；原状态数据库不删除、不重建，不更改旧冻结事实。
- 使用临时目录和合成行情验证边界；真实运行仅用于缓存闭环，不把合成结果计入真实研究结论。
- 按阶段更新本文件的状态与验收记录；实现完成后跑研究模块及相关回归测试，再执行一次真实缓存 cycle，检查 JSON 与 Markdown。
- 恢复工作时先阅读本文件和 git diff，按未完成状态继续，不能因某阶段真实历史等待而漏掉独立可实施工程。
- 后续补 ETF 份额/净值、申赎和交易所完整清单属于另一个数据扩展批次；本批六项不能宣称已经获取这些数据。
