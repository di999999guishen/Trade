# 全量 ETF 分类评价与粗筛细化

本轮把全量评价接入 `cycle` 的正式筛选之前，修复行情简称漏识别和同指数简称重复占位。所有输入记录先得到适用规则与数据状态，再决定是否具备进入某条候选通道的条件。每类有评价标准，不等于每类必须买入一只，也不等于数据缺失可以填成正面分数。

## 数量的含义

- **1715**：本次验证使用的 2026-10-30 行情快照记录数，全部得到评价。
- **15**：此前长期收益实验的固定历史样本池，不是生产粗筛范围，不是 agents 数量。该池不足以证明全市场收益改善。
- **20**：当前 `workflow.prediction_top_n`；预测层候选上限。
- **10**：当前 `workflow.agent_top_n`；多智能体分析上限，实际数量还受历史数据门限和运行配置约束。

## 评价标准

| 类别 | 专属标准 | 数据不足时 |
|---|---|---|
| 股票宽基、行业、主题、策略、主动 | 5/20/60/120 日价格强弱、同类相对表现、趋势连贯度、多周期一致性、20 日均价偏离、5 日涨幅相对波动、成交承接、5 个已观测日期资金持续性 | 短历史分层；缺失维度逐项记录 |
| 国债、政金债、信用债、其他债券 | 到期收益率、久期、信用利差、流动性；可转债另加转股溢价及价格趋势 | 不把债券价格动量当成收益率；保留流动性评价 |
| 货币 | 披露七日年化收益、流动性、交易成本 | 不用涨幅排序；披露收益缺失明确标记 |
| 黄金、商品期货、其他商品 | 趋势、波动、折溢价；期货增加展期收益 | 不猜测期限结构和展期收益 |
| 跨境覆盖层 | 对各资产类别额外检查折溢价、底层市场和相关汇率 | 时区及数据时点不齐时保留待补 |
| 多资产、特殊结构、无法识别 | 权重/集中度与产品身份核验；报价与流动性兜底 | 保留记录，不强行归入股票类 |

共同检查报价有效性、真实成交额、持续流动性和买卖价差。所有披露型数据必须有数值、对应日期、首次可得时间及来源 URL；未来数据、过期数据不会进入当前评价。价差未采集时保持缺失，不视为零成本。归类依据仍是行情板名称和少量明确代码，尚未逐只以基金合同确认。

## 主流程与凌晨 agents

`run_pipeline.py → cycle → 全量分类评价 → 冻结粗筛 → 预测/agents → 结算与汇总`

- `cycle.artifacts` 保存全量 JSON 和可读 HTML；主流程报告显示覆盖率和报告链接。
- 冻结粗筛保存评价文件路径及 SHA-256。凌晨独立 `run-agents` 也能读取当时的评价，不能用后来生成的文件替换。
- 新字段作为 `category_assessment` 进入 agents 的证据。缺失值与“不是收益预测”的说明一起传递。
- 分页重复、服务端总数不符、标准化丢记录会明确失败，避免把残缺列表标为全量。
- 全量范围指输入行情板的全部记录；本次没有完成交易所上市名录逐项对账，不能宣称覆盖所有上市或已退市产品。

单独查看：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 run_research.py assess-universe
```

主流程仍使用 `run_pipeline.py`。本次没有迁移调度、启动付费 agents 或提交交易。

## 收益优化的判断与后续顺序

本轮已确认覆盖和证据传递改善，尚未证明净收益提升。分类修复和指数简称归并会改变候选池；新增细项目前用于分类评价与 agents 上下文，**没有直接重配生产收益评分权重**。此前固定 15 只实验中，缩小持仓数量、堆叠多因子、按过去收益选参数并未稳定胜过基线，不能据此推断全量策略优劣。

优先补齐全量历史和基金合同/指数身份，再补折溢价、盘口价差、申赎份额、久期及收益率。新闻流继续以实际发布时间和首次获取时间冻结；下一步更值得检验的是国内政策/行业事件与底层持仓的关联、重复转载消重、事件之后价格已反映多少，而不是简单按新闻条数或情绪加分。现有新闻源覆盖仍偏宏观与能源，尚未完成全行业扩展。

新评分策略需使用按当时可得信息重建的历史样本，扣除交易成本后滚动验证，单独报告收益、回撤、换手率和数据覆盖。当前样本有存续偏差、部分旧价格口径未认证，不能把离线观察当成无偏样本外收益证明。
