# 分阶段实施路线与开发任务清单

状态：实施计划，未开始安装新框架。工期为一名熟悉Python开发者配合AI的粗估，不含数据订阅审批、供应商清洗等待及前向模拟观察期。

## 1. 阶段与停止条件

| 阶段 | 参考投入 | 顺序与任务 | 完成产物 / 退出条件 |
|---|---|---|---|
| P0A 基础 | 3–5工作日 | M00 → M01 → M02 → M03 | 独立环境、快照、数据字典、18只ETF覆盖报告；缺数据也能明确失败 |
| P0B 规则MVP | 4–7工作日 | M07基础 → M06 → S1 → M08基础 | 同口径基准与S1、5/10/25bps成本情景、冻结信号、离线复现 |
| P1A 因子 | 5–8工作日 | M04 → S2 → 因子诊断 | 因子库、IC/分组/换手、去冗余和消融；不要求必须发现alpha |
| P1B 模型 | 5–8工作日 | 标签/分割 → M05 → S3 | LightGBM对规则基线、无泄露滚动报告；未胜过基线就保留简单模型 |
| P2A 复核 | 5–10工作日 | LEAN数据/目标权重适配 → 独立账本 | 现金/行动/费用与持仓对账，结论更新；系统性差异未解决就不升级 |
| P2B 运行 | 3–5工作日开发，随后持续观察 | M10 → M09可选 → 前向冻结 | 每日可恢复运行、运行状态、影子实验；至少数月观察，不能压缩为开发几天 |
| P3 扩展 | 按数据与策略另估 | S4/S5股票、S6做空、S7期权、S8自动因子 | 每种扩展独立数据验收与交易约束，不共享一个“通过”标签 |

合理的第一目标是约2周交付免费ETF规则MVP，约6–10周形成较完整研究与复核体系。数据缺陷和Windows/WSL部署可能增加工期；不把这个估算当交付承诺。

## 2. 依赖图

```text
环境/配置 → 原始快照 → 价格/日历/池 → 基准回测
                                  ├→ S1组合 → 成本报告 → MVP
                                  └→ 因子库 → 标签/分割 → S2/S3
MVP + 冻结目标权重 → LEAN原始价格账本 → 前向模拟
证据接口/历史事件 → Agent影子实验（不阻塞无LLM主线）
新数据与风险模型 → 做空 / 期权 / 自动因子研发
```

基础schema冻结后，可以并行写数据质量测试、因子纯函数、报告模板。共用文件与接口的修改应由一个负责人整合；不要让多个AI同时修改同一配置和账本。

| T05 数据清洗 | 原始快照 | 规范表、价格basis报告、交易日池 | 成立前无数据；未来数据改动不改过去入池 |
| T06 Qlib适配 | 规范表 | REG_US研究dataset、显式费用/成交口径 | 标签与信号shift一次，禁A股涨跌停/100股默认 |

| T08 S1 | 策略目录S1 | 因子、目标权重、约束理由 | 不足标的留现金，日评估不强制交易 |

## 4. CLI与运行手册设计

以下命令**待开发完成后才能执行**，名称用作模块验收契约：

```text
quant-research doctor --offline
quant-research data fetch --config configs/etf_free.json
quant-research data validate --snapshot <snapshot_id>
quant-research universe audit --snapshot <snapshot_id>
quant-research factors build --config configs/etf_free.json --snapshot <snapshot_id>
quant-research backtest --strategy s1_etf_momentum --snapshot <snapshot_id>
quant-research evaluate --run <run_id> --cost-scenarios 5,10,25
quant-research train --strategy s3_etf_lgbm --split <split_manifest>
quant-research export-lean --run <run_id>
quant-research reconcile --research-run <id> --lean-run <id>
quant-research daily --config configs/etf_free.json
quant-research replay --manifest outputs/<run_id>/manifest.json --offline
```

部署实现后提供PowerShell与WSL各自独立命令，不混用两套路径。不要在根项目环境直接 `pip install --upgrade` 全部依赖。源码与依赖版本由首次兼容性验证决定，本方案不猜测未经安装的精确版本号。

## 5. 日常研究周期

1. 调度器用America/New_York日历判断是否完成交易日和数据可得；中国时区只用于用户显示。
2. 获取行情和行动，数据质量检查失败则生成失败报告，停止新增信号/风险。
3. 固定快照；只计算通过质量门标的，记录未通过原因。
4. 载入此前批准的策略/模型版本，不每天自动全参数调优。
5. 输出完整目标权重、风险校验与差异说明；冻结manifest。
6. 下一有效交易时段模拟执行；延迟任务不倒填成交。
7. 收盘后更新现金/持仓/净值、费用、对照基准和前向结果。
8. 归档输入输出与配置。失败可从明确阶段恢复，不能重复模拟同一订单。

日报至少显示：数据日期、研究状态、持仓/目标差异、成本、风险暴露、与SPY/QQQ表现差异、样本外覆盖和待解决问题。首页不能将模拟收益显示成真实交易收益。

## 6. 何时进入下一阶段

**从MVP到因子模型**：数据和账本测试通过，基准可复现，S1已形成完整报告。无需先证明S1能盈利，但需知道简单基线表现。

**从模型到模拟交易**：冻结模型/参数，完成样本外报告、数据不足说明与独立账本核对。工程通过和投资绩效分别决策；业绩不达标可继续作为研究运行，不能换标签称正式策略。

**从免费数据到购买数据**：提交候选策略、缺失字段、免费数据限制、预期改变的结论和预算；届时以具体供应商方案决定，当前不产生采购。

**做空/期权**：先补相关历史数据与交易机制测试。允许研究不等于已设置券商交易权限；真实接入前需账户能力、本金和风险预算。期权没有历史链时只能做教学/情景收益图，不能称历史策略回测。
